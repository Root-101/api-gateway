* 6.x:
    * 6.0.0:
        * **DATE** :date: : 2026-11-10.
        * **Deploy** :warning: : Deploy together with the web console (`console`) of this same release: it relies on the `401`/`403` with CORS headers to log out. Building now needs a **JDK 25** (Gradle finds the installed ones).
        * **Structure** :file_folder: : Repository split in two folders: `gateway` (backend, with its Gradle build and `Dockerfile`) and `console` (web console, was `tools/api_gateway_front`). :warning: Deploys from the repository need the new root directories (Railway: `/gateway` and `/console`). Run `./gradlew` from `gateway`. A single `ROADMAP.md` in the root for both.
        * **Versions** :arrow_up: : Upgrade to the latest versions: Java `21` → `25` (LTS), GraalVM CE `25` for the native image, Spring Boot `3.5.14` → `4.1.2` (Spring Framework `7.0.10`, Spring Security `7.1.2`, Jackson `3.1.7`), Spring Cloud `2025.0.2` → `2025.1.4` (Gateway `4.3.4` → `5.0.4`), Gradle `8.14.2` → `9.8.2`, native build tools `0.11.3` → `1.1.18`, `dev.root101.commons` `5.5.3`, Flutter `3.47.9`, GitHub Actions to their latest majors. From the Spring Boot BOM (no hardcoded versions): Flyway `12.4.0`, Postgres driver `42.7.14`, r2dbc-postgresql `1.1.3`, Lombok `1.18.48`, Testcontainers `2.0.5`, JUnit `6.0.3`. Same API contract: the json mapper keeps the Jackson 2 defaults.
        * **Logs** :memo: : Fixes: requests to routes without rewrite-path were not logged, the final route applied the rewrite to `uri + path`, and logs were lost with a long `X-Forwarded-For` (now the first ip is used).
        * **Logs** :memo: : Saved out of the request path: bounded in-memory queue, inserted in batches (if full, logs are dropped with a warning; pending ones are saved on shutdown). New index on `requested_at` (migration `V3`) and old logs deleted in batches.
        * **Logs** :memo: : `POST /http-log/search`: `size` capped by the new `MAX_LOGS_SEARCH_SIZE` (default `10000`), `response_code` with fewer than 3 digits is a prefix (`4` = `400`..`499`, `47` = `470`..`479`), non numeric → `400`, `%` and `_` are literal.
        * **Routes** :twisted_rightwards_arrows: : Loaded before the server accepts traffic, no more `404`s after each deploy (if they can't be loaded, the startup fails). `multi-add` is all or nothing. Fixes: editing with the name of another route → `409` (was `500`), deleting with an uppercase id kept the route active until restart. New `PUT /routes`: replaces every route with the ones in the body, all or nothing.
        * **Auth** :lock: : Fixes: admin auth was applied to any path *containing* the admin path, malformed `Basic` header → `401` (was `500`), the auth filter ran twice. `401`/`403` include the CORS headers and no longer trigger the browser popup.
        * **API** :warning: : Breaking changes in the admin api. `GET /routes/{id}` returns the same object as `GET /routes` (`id` and `rewrite_path`, no more `route_id` and flat rewrite fields). `POST /auth/login` with wrong credentials → `401` (was `403`). `POST /http-log/search`: `route_id` is an exact match, `400` if it's not a uuid or `NO-ROUTE`.
        * **Auth** :lock: : `POST /auth/login` returns a token (`token`, `expires_in`) to send as `Authorization: Bearer`, valid for the new `ADMIN_TOKEN_MINUTES` (default `480`). In memory: a restart invalidates them. Basic auth still works. A correct login resets the failed attempts.
        * **Logs** :memo: : New `route_id` column generated from `route`, with its index (migration `V4`): the search by route no longer uses `LIKE` over the json.
        * **Auth** :lock: : Brute force lockout per client ip → `429` (new `ADMIN_MAX_FAILED_ATTEMPTS`, default `10`, and `ADMIN_LOCKOUT_MINUTES`, default `15`). Credentials compared in constant time. The default password is no longer printed, and there are warnings when running with default admin or db credentials.
        * **Errors** :rotating_light: : `500`s no longer expose internal messages and are logged. Upstream down → `502`, upstream too slow → `504` (was `500` with the internal host). String errors sent as UTF-8 `text/plain`; nothing is written over a response already sent.
        * **Gateway** :hourglass: : New `GATEWAY_CONNECT_TIMEOUT_MS` (default `10000`) and `GATEWAY_RESPONSE_TIMEOUT` (default `60s`, empty = no timeout). :warning: Before there was no response timeout: raise it for services with slower endpoints.
        * **Gateway** :hourglass: : New `CORS_ALLOWED_ORIGINS` (default `*`, same as before). CORS headers sent by an upstream are no longer duplicated.
        * **Errors** :globe_with_meridians: : Every text of the admin API in English and Spanish, picked by `Accept-Language` (`es` → Spanish; anything else, or no header → English): `title`, `detail` and the `422` violation messages (bean validation and the route rules), including the `401`/`403`/`429` of the security layer. Texts in `messages.properties` and `messages_es.properties`. Statuses, keys and `fieldName`s don't change. Violation messages now start with a capital letter (`Must not be blank`), the lockout `429` says the wait in minutes from one minute on (`try again in 10 min`, was `559 s`; `Retry-After` stays in seconds), and a request that can't be read for another reason says `The request can't be read` instead of Spring's text.
        * **Ops** :stethoscope: : Health check `GET /{ADMIN_PATH}/health` (no auth, not logged). Server logs with SLF4J. The docker image runs as non-root and has a `.dockerignore`.
        * **Docker** :whale: : `docker-compose`: the gateway waits for Postgres to be healthy, the gateway and the console have their own healthcheck (the console starts once the gateway is healthy), the new env vars are listed, and the web console gets its config at runtime (`environment:`, one image for every environment). Final image on `debian:trixie-slim`. Native image built with `-H:+SharedArenaSupport`: without it every route to an HTTPS upstream returned `500`.
        * **Code** :broom: : Dependencies cleanup (test libraries out of the production binary, Lombok only at compile time, Spring Cloud from its BOM) and code cleanup without behavior changes.
        * **Tests** :test_tube: : Unit tests (`./gradlew test`) and integration tests with Testcontainers (`./gradlew integrationTest`, Docker required): 116 tests, 96.2 % lines / 87.9 % branches, with a coverage gate in `check`.
        * **CI** :construction_worker: : GitHub Actions: tests and coverage gate, web console build, and the native docker image with a smoke test. The Postman collection is only for trying the API by hand, not run in the CI. A version tag publishes the images on GHCR (`api-gateway` and `api-gateway-console`, amd64) once the CI passes. The console's `pubspec.lock` is now versioned and enforced in the CI and the docker build.
        * **Docs** :books: : README: new env vars, security and timeouts, health check, single-instance note, how to run the tests, and a new documentation improvements section, starting with the supported protocols (HTTP, SSE and WebSocket yes; HTTP/2, gRPC and raw TCP/UDP no). Postman collection (now `docs/postman/`) rewritten, to import and try by hand: checks on every request, no fixed ids, cleans up after itself. Full documentation to the standard of the other Root-101 projects: README rewritten (what it does, run it, configuration, versions; why the database is set in parts: R2DBC and Flyway's JDBC URL are built from the same variables), `docs/api.md` (every admin call with real requests and responses, errors, routing and what gets logged), `docs/console.md` (every screen, its URL and the calls it makes), `docs/brand.md` (icon, colors, type), `docs/design/` (the console design exported from its Claude Design canvas: 20 screens, a PDF, the icon as SVG and PNG, and `tool/export.py` to regenerate them), and new `SECURITY.md`, `DECISIONS.md` and `CONTRIBUTING.md`. `doc/` moved to `docs/`; the old console screenshots and `detailed-api-docs-README.md` removed.
        * **API** :warning: : The admin API standardized, like the other Root-101 services. Every error is a Problem Details (RFC 9457, `application/problem+json`: `type`, `title`, `status`, `detail`, `instance`), a `422` with `violations` (`fieldName` as the JSON path, `message`); no more plain text, bare lists, empty `401`s or `null` fields. `POST /routes` → `201` with the route, `POST /routes/multi-add` renamed `POST /routes/batch` → `201` with the list, `PUT /routes/{id}` and `PUT /routes` answer what they saved, `DELETE /routes/{id}` → `204`. A route id that isn't a UUID → `400` (was `404`). `PUT /routes` keeps the id of a route whose name exists, so its logs still find it. `POST /http-log/search` replaced by `GET /http-logs` with the filters in the query (`page`, `size` (default `50`), `status`, `method`, `query`, `route_id`, `from`, `to`; empty = no filter), answering `items` (was `page_content`); `method` and `query` are case-insensitive. Login answers `access_token`, `expires_in` and `expire_at` in milliseconds (was `token` and seconds). Health is `{"status":"up"}` / `503 {"status":"down"}` (Actuator removed). Dates always in UTC (`Z`).
        * **Auth** :lock: : The lockout only blocks new tries of the credentials (login and Basic auth): a valid token and the health check keep working from a locked IP. The `429` sends `Retry-After` and says the wait. Wrong Basic credentials → `401` (was `403`).
        * **Errors** :rotating_light: : No internals in `detail`: a path no route matches says `No route matches /x` (was Spring's static resources message), a body that can't be read names the field instead of the Java types, a response timeout doesn't show its configured duration. Replacing or deleting a route this instance didn't hold in memory no longer fails half applied. `created_at` answered to the microsecond, as stored.
        * **Docs** :books: : `docs/api.md`, the Postman collection, README, `SECURITY.md` and `DECISIONS.md` updated to the standardized API. The identity sheet of the brand, translated to English in the design canvas, exported to `docs/design/brand/images/identity-sheet.png` and shown in `docs/brand.md`. The README opens with the identity, cropped to its content (`docs/design/brand/images/banner.png`), instead of the icon and a text title.
        * **Security** :lock: : Fixes from a quality and a security audit. The lockout counts each try of the credentials before checking it (atomically), so concurrent guesses can't pass the limit, and only correct credentials reset it: a plain `OPTIONS` to the login used to clear the count (unlimited guesses). A stray `Authorization` header on the health check no longer counts. Admin requests the security layer rejects (401, wrong Basic, the 429) are now logged: the HTTP logs filter runs before the security chain; only real CORS preflights are left out of the logs (any other `OPTIONS` is logged). The default-admin-password warning also fires when only the password is the default. A correct login clears the failed count before its response is sent: it used to clear it after, so a try sent right after the response could be counted and then wiped.
        * **CORS** :warning: : One policy (`CORS_ALLOWED_ORIGINS`) for every path, the admin API and the proxied routes, now without credentials. It used to reflect any origin with credentials, so any page could read a cookie-authenticated service through the gateway. The `Access-Control-*` headers a service sends are replaced by the gateway's (the `DedupeResponseHeader` default filter is gone). Leaving the proxied routes to their services' CORS, as tried first, broke every JSON request from a browser: the gateway answers the preflight itself, it never reaches the service. A CORS policy per route is in the roadmap. A request from an origin not allowed gets a `403` with an empty body, documented in `docs/api.md`.
        * **Routes** :twisted_rightwards_arrows: : A route the gateway can't build is rejected with a `422`: a `path` that isn't a valid path pattern or doesn't start with `/` (it was saved but never matched a request), a `rewrite_path.replace_from` that isn't a valid regex (one of these used to stop every route change and, after a restart, break every proxied request), and a `uri` with a path (the gateway ignores it, so it used to be silently dropped). A bad row edited into the database by hand only skips itself (`fail-on-route-definition-error: false`).
        * **Routes** :twisted_rightwards_arrows: : New `POST /routes/validate`: checks a route with the same rules as create and edit without saving it (`204` or the `422`), and isn't logged. The console's route form validates each step with it.
        * **Logs** :memo: : The log search counts matches up to 100000 instead of scanning the whole table on every page: `total_elements` stops there and the new `total_capped` says so.
        * **Ops** :stethoscope: : `docker-compose.yml` publishes every port on `127.0.0.1` only (PostgreSQL with its public sample password was reachable from other machines). CI and release: actions pinned to commit SHAs, read-only token by default (only the image job can write packages), and the smoke test fixed for the new API (`GET /http-logs`, `"status":"up"`).
        * **Code** :broom: : Dead code removed (`RouteRepo.findByRawId`, `RouteUseCase.getCacheRoutes`, `HttpLogEntity.setRawRoute(RouteLog)`, an empty `@Size()`), and unused dependencies and switches (`@EnableReactiveMethodSecurity`, the `HttpLogSearchRequest` hint). `spring-cloud-loadbalancer` stays, with a comment: without it the native image crashes at startup (segfault parsing the annotations of the gateway's no-load-balancer auto-configuration). The admin auth filter is a plain `WebFilter`.
        * **Web console** :computer: : Bug fixes, security, robustness and tests. The docker image generates `env.js` at container start (`GATEWAY_SERVICE_URL`, `ADMIN_PATH`, `SESSION_TIMEOUT_MINUTES`), so one image works for every environment. Texts migrated to slang, and routes can be edited by url (`/routes/:id/edit`).
