The maintenance `503` is always `maintenance.active` and the lockout `429` `auth.locked`. Every code in `docs/api.md`, "Error codes". :warning: Breaking for clients that read `violations`: the console of this version already reads `errors`.

    * 6.1.0:
        * **DATE** :date: : 2026-11-18.
        * **Gateway** :jigsaw: : Add-ons: optional features on top of the routing, per route and for the whole gateway. Every route has an `addons` field with every type (`null` when not configured), and the gateway's are in `GET /{ADMIN_PATH}/addons`. Each one is set with `PUT`, removed with `DELETE` and turned on or off with `POST .../enable` and `.../disable` (`404` when not configured), under `/{ADMIN_PATH}/routes/{id}/addons/{type}` and `/{ADMIN_PATH}/addons/{type}`. Create, edit and batch ignore `addons` (edit keeps them); the restore (`PUT /routes`) matches the routes by name: no `addons` keeps them, a key `null` deletes it, a key left out keeps it, an unknown key is ignored. Stored in a new `addon` table (migration `V5`, what the admin sets in `config` apart from what the gateway writes in `state`); a row that can't be read is skipped and never stops the gateway. Decision 17 in `DECISIONS.md`, see `docs/api.md`, "Add-ons".
        * **Gateway** :construction: : Maintenance add-on, per route and for the gateway: every request gets a `503` right away (Problem Details, the admin's `message` or a default text in the request's language, and `Retry-After` while the optional `retry_after` is ahead) instead of reaching the service. Answered with a read-only `default_message` and `state` (`enabled_at`, `disabled_at`). It never turns off by itself, and the gateway's wins over a route's. The admin API, the console and the health check are never stopped, and a path with no route stays a `404`.
        * **Gateway** :stethoscope: : Health check add-on, routes only: the gateway calls `GET {uri}{path}` every `interval_seconds` (10 to 3600) while `enabled` and keeps the last result in `state` (`checked_at`, `up` for a `2xx`, `status`, `null` when it doesn't answer in 5 s, `millis`). `POST .../run` calls it now, and editing a route's `uri` calls it again before answering. Only the route's host, no redirects, no client headers, body thrown away (decision 18). It never changes the routing.
        * **Gateway** :vertical_traffic_light: : Rate limit add-on, per route and for the gateway: each client IP can make `limit` requests per `period` (`second`, `minute`, `hour`), up to `burst` at once; past it, a `429` with `Retry-After`, without reaching the service. The gateway's counts each IP on every route together (a request a route's limit stops doesn't count for it); with both, both apply. Only proxied traffic, after the maintenance. Counts in memory, per instance, at most 100,000 at once; any change to a rate limit, a restore or deleting a route starts them again (decision 19).
        * **Gateway** :globe_with_meridians: : CORS add-on, for the gateway and per route: `{"enabled", "allowed_origins", "allow_credentials"}`, methods and headers stay `*`. The gateway's always exists (only `PUT /{ADMIN_PATH}/addons/cors`) and covers the admin API and every route without its own; a route's covers only that route and can allow credentials with explicit origins. `400` for credentials with an origin that lets in any site (`*`, or a `*` in the host other than `*.domain.com`), and for a `PUT` of the gateway's from a browser whose `Origin` the new list leaves out. Applied from memory, no restart; the `503` and `429` carry the headers too, a path with no route gets none. Decision 20 (supersedes 15).
        * **Gateway** :lock: : With the default `TRUSTED_PROXIES=.*` the client IP is the last `X-Forwarded-For` entry, not the first one, which the client can write itself: a faked header no longer dodges the rate limit or the lockout, nor fakes the IP in the logs.
        * **Console** :computer: : Console `6.1.0` for the add-ons: a panel per route and for the gateway to add, edit, turn on or off and remove maintenance, health check, rate limit and CORS, with badges on the route cards; a new gateway map as the start screen, with a branch per route showing whether it forwards, is in maintenance or is down; and a banner while the deprecated `CORS_ALLOWED_ORIGINS` is still set.
        * **Deploy** :warning: : `CORS_ALLOWED_ORIGINS` is deprecated (removed in 7.0): on the first 6.1.0 start its origins (or `*`) become the gateway's CORS add-on; from then on it is ignored, with a warning in the log, and the gateway's `cors` answers a read-only `env_var` (`name`, `origins`, `matches`) for the console. Behind two or more proxies, set `TRUSTED_PROXIES` to their IPs (see `SECURITY.md`); behind one (Railway) nothing changes.
        * **Versions** :arrow_up: : PostgreSQL `16` → `18` in `docker-compose.yml`, the tests and the CI. :warning: A `postgres_data` volume made by 16 can't be opened by 18: delete it (`docker compose down -v`) or dump and restore the data.
        * **Tests** :test_tube: : `MaintenanceIT`, `HealthCheckIT`, `RateLimitIT`, `CorsIT`, `TokenBucketTest` and `CorsUseCaseImplTest`, and the add-ons in the mutation rules and the Postman collection. Each integration test uses its own client IP (`IntegrationTest.uniqueIp()`): a shared one could be locked out by another test.
        * **Build** :hammer: : `--enable-native-access=ALL-UNNAMED` for `bootRun` and the tests (Netty's warning on Java 25), and the `HV000271` warning from Spring Cloud Gateway's own classes silenced.
        * **Code** :broom: : Add-ons under `features/addons`, the common parts in `features/addons/base`. Dead code removed: the `PROFILE` variable (it changed nothing, see the README's removed variables), unused parameters, methods and imports, and `git` in the build image. `TRUSTED_PROXIES` added to `ENV_TEMPLATE`.

    * 6.0.0:
        * **DATE** :date: : 2026-11-12.
        * **Deploy** :warning: : Deploy together with the console of this same release. Building needs a **JDK 25**. The repository is split in `gateway` (backend) and `console` (web console, was `tools/api_gateway_front`): deploys from the repository need the new root directories (Railway: `/gateway` and `/console`).
        * **API** :warning: : Breaking changes, the admin API standardized like the other Root-101 services. Every error is a Problem Details (RFC 9457, `application/problem+json`), a `422` with `violations` (`fieldName`, `message`), in English or Spanish by `Accept-Language`. `POST /routes` → `201`, `POST /routes/multi-add` renamed `POST /routes/batch` → `201`, the `PUT`s answer what they saved, `DELETE` → `204`, a route id that isn't a UUID → `400`. `GET /routes/{id}` returns the same object as `GET /routes`. `POST /http-log/search` replaced by `GET /http-logs` with the filters in the query (a `status` with fewer than 3 digits is a prefix), answering `items`. Login answers `access_token`, `expires_in` and `expire_at` (ms), wrong credentials → `401`. Health is `{"status":"up"}` / `503`. Dates in UTC.
        * **Routes** :twisted_rightwards_arrows: : Loaded before the server accepts traffic (no more `404`s after a deploy). New `PUT /routes` replaces every route, all or nothing (a route whose name exists keeps its id), and `POST /routes/validate` checks one without saving it. Batch is all or nothing. A route the gateway can't build gets a `422` (a bad path pattern, a bad regex, a `uri` with a path); a bad row in the database only skips itself. Fixes: editing with another route's name → `409` (was `500`), deleting with an uppercase id.
        * **Auth** :lock: : `POST /auth/login` gives a Bearer token valid for `ADMIN_TOKEN_MINUTES` (default `480`, in memory); Basic auth still works. Brute force lockout per client IP → `429` with `Retry-After` (`ADMIN_MAX_FAILED_ATTEMPTS`, default `10`, and `ADMIN_LOCKOUT_MINUTES`, default `15`), counted atomically on the credential tries only, reset only by correct ones. Credentials compared in constant time, and warnings with the default admin or db credentials. Fixes: the admin auth applied to any path containing the admin path, a malformed `Basic` header was a `500`, the filter ran twice; `401`/`403` carry the CORS headers and no longer open the browser popup.
        * **CORS** :warning: : New `CORS_ALLOWED_ORIGINS` (default `*`): one policy for the admin API and the routes, without credentials (it used to reflect any origin with credentials). The services' `Access-Control-*` headers are replaced by the gateway's.
        * **Gateway** :hourglass: : New `GATEWAY_CONNECT_TIMEOUT_MS` (default `10000`) and `GATEWAY_RESPONSE_TIMEOUT` (default `60s`, empty = none). :warning: Before there was no response timeout. Upstream down → `502`, too slow → `504`, and no internals in the `500`s or any `detail`.
        * **Logs** :memo: : Saved out of the request path (bounded queue, batched inserts, flushed on shutdown) and old logs deleted in batches. The search is capped by `MAX_LOGS_SEARCH_SIZE` (default `10000`), uses a new `route_id` column (migrations `V3` and `V4`) and counts up to 100000 (`total_capped`). Admin requests the security layer rejects are logged. Fixes: routes without rewrite-path weren't logged, the rewrite applied to `uri + path`.
        * **Ops** :whale: : Health check `GET /{ADMIN_PATH}/health`. Docker image on `debian:trixie-slim`, non-root, native with `-H:+SharedArenaSupport` (HTTPS upstreams returned `500` without it). `docker-compose`: healthchecks and start order, ports only on `127.0.0.1`, and the console's config at runtime.
        * **Console** :computer: : Bug fixes, security, robustness and tests. Its config is read at container start (`env.js`: `GATEWAY_SERVICE_URL`, `ADMIN_PATH`, `SESSION_TIMEOUT_MINUTES`), so one image works for every environment. Texts with slang, and routes editable by url (`/routes/:id/edit`).
        * **Versions** :arrow_up: : Java `21` → `25` (LTS), GraalVM CE `25`, Spring Boot `3.5.14` → `4.1.2`, Spring Cloud `2025.0.2` → `2025.1.4` (Gateway `5.0.4`), Gradle `9.8.2`, Flutter `3.47.9`, GitHub Actions to their latest majors. Same API contract: the json mapper keeps the Jackson 2 defaults.
        * **Tests** :test_tube: : Unit tests and integration tests with Testcontainers (`./gradlew integrationTest`, Docker required), with a coverage gate in `check`.
        * **CI** :construction_worker: : GitHub Actions: tests and coverage gate, the console build, and the native image with a smoke test; a version tag publishes both images on GHCR. Actions pinned to commit SHAs, read-only token by default. The console's `pubspec.lock` is versioned and enforced.
        * **Code** :broom: : Dependencies and dead code cleanup, no behavior changes. `spring-cloud-loadbalancer` stays: the native image crashes at startup without it.
        * **Docs** :books: : Full documentation to the standard of the other Root-101 projects: README rewritten, `docs/api.md`, `docs/console.md`, `docs/brand.md`, `docs/design/` (the console design), `SECURITY.md`, `DECISIONS.md` and `CONTRIBUTING.md`. Postman collection in `docs/postman/`, to try by hand. `doc/` moved to `docs/`.
